# janzowm — janzo window manager

A macOS tiling window manager. Combines app focusing (like Raycast) and window tiling (like Rectangle) into a single key-chord interaction. See README.md for user-facing docs.

## Design Constraints

- **"Full screen" = maximized, NOT macOS native fullscreen.** It fills the screen's visible area (excluding menu bar and Dock). It must never create a new desktop/space.
- **Window moves before activation.** When tiling via chord (cmd+N + position), the window is repositioned *before* being brought to front, so it appears already in place.
- **Hold-based chord, not timeout-based.** A 500ms timeout approach was tried and discarded — it added noticeable delay to plain focus. The current hold-based approach (hold cmd → press position key) eliminates this.
- **Two-slot mental model for auto-rearrangement.** There are two slots: left and right. Full screen occupies both. When a half tile displaces a full-screen app, the full-screen app shrinks to the opposite half. When a half tile replaces another half tile, the previous occupant simply loses focus (no repositioning). Only full-screen apps auto-reposition when displaced.
- **Multiple apps can be fullscreen at once.** Displacement picks the most recently fullscreen-frontmost app on the same display. The list survives displacement — successive half-tile chords pop apps off in reverse-recency order, not just the latest one.
- **Slot writes only at action boundaries.** `WindowTiler.tile()` is geometry-only — never mutates `slots`. Slot upserts/removes happen at: (a) `HotkeyManager.onBeforeAction` (snapshots frontmost before any focus/tile chord), and (b) `onFocusChanged`'s defocus path (snapshots the just-defocused app). Adding slot writes inside `tile()` reintroduces the test-09 class of bug.
- **AppKit→CG coordinate conversion always uses primary screen height.** CG coordinates have origin at the primary screen's top-left. The y-flip formula `cgY = primaryHeight - appKitY - height` must use `NSScreen.screens[0].frame.height`, not the current screen's height, even when tiling on a secondary screen.
- **Do not hardcode app assignments.** App-to-key mappings are user-configurable via Settings UI and stored in UserDefaults.
- **Every change must be assessed for multi-screen correctness.** Before considering a change done, verify that it works correctly when multiple screens are connected — coordinate conversions, screen selection, slot tracking, and window positioning must all account for the multi-screen case.
- **Prefer Quartz over AX for reads.** Window enumeration, frames, owning pid, and z-order are available from `CGWindowListCopyWindowInfo` (wrapped in `QuartzWindowList`). AX calls (`AXUIElementCopyAttributeValue` etc.) IPC synchronously into the target app and block the main thread until either a response or `axMessagingTimeout` (0.1s) — a hung or busy foreground app multiplies that timeout by the number of windows walked. Quartz reads go to WindowServer instead, with no per-app IPC, so the cost is constant regardless of how many windows the app has. Reserve AX for things Quartz can't do: reading kAXFocusedWindow, mapping an AXUIElement to a CGWindowID via `_AXUIElementGetWindow`, and writing position/size. Commit 9088b8e (SnapManager) and the per-window slot rewrite both moved enumeration off AX for this reason.
- **Do not invoke "well-known macOS quirks" without a citable source.** When diagnosing a flake or an unexpected API result, do not justify a code change with phrases like "known macOS quirk", "documented bug", "transient race", or "stable since 10.X" unless you can point to a specific radar, Apple doc, mailing-list thread, or piece of source from a known project. Past attempts to do this in janzowm fabricated precedent from a single log line, which produced misleading commit messages and wasted review time. State only what you actually observed (timestamp + log line), and if you're hardening defensively, label it that way — not as patching a known issue.

## References

- **[Rectangle](https://rectangleapp.com/)** — similar macOS window manager, useful as reference for solving window management problems. Source available at `/Users/giovanni.beri/workspace/Rectangle` (clone from `https://github.com/rxhanson/rectangle` if needed).
- **Integration-test stub apps.** Integration tests use stub victim apps under `integration-tests/stubs/` instead of real Apple apps, for determinism. Build via `make build-test-stubs`.
- **Integration-test filename prefixes must be unique across `test-cases/` and `test-cases/multi-screen/`.** `make test-integration TEST=NN` globs both directories, so two tests sharing the same `NN_` prefix both run (and the intended filter becomes ambiguous). Pick the next free number when adding a test.
- **Screen inspection helper.** Use `integration-tests/screen-info-helper.swift` to inspect connected screens when investigating or developing multi-screen behavior. Subcommands: `screen-count`, `expected-rect`, `expected-rect-on <idx> <left|right|full>`, `screen-of <x> <y> <w> <h>`. Reports the same NSScreen view (indices, visibleFrame-derived CG rects) that janzowm sees at runtime.
